Qiita へ投稿する記事を書きます。

## なぜこのスキルがあるか

Qiita の記事は、構造と記法が決まっていると読みやすく、書くのも速いです。
uhooi の記事はどれも同じ骨格でできています。この骨格をそのまま使うことで、毎回ゼロから構成を考えずに済みます。

## 手順

1. **テーマを確認する**。何について書くか曖昧なら、書き始める前に聞く
2. **事実を確認する**。バージョン、コマンド、公式ドキュメントの記述を確かめる。推測で書かない
3. **参考にした URL を控える**。あとで「参考リンク」に漏れなく書く（後述）
4. **保存先を決める**（後述）
5. **front matter を書く**（後述）
6. **本文をテンプレートに沿って書く**（後述）
7. **文体を整える**。`uhooi-writing` スキルを使う。これは必須
8. **セルフチェックする**（末尾のチェックリスト）

## 保存先

- カレントに `public/` があり、`package.json` に `qiita-cli` があれば `public/{スラッグ}.md`
- そうでなければカレントに `{スラッグ}.md`
- スラッグは内容がわかる英小文字ケバブケース（例: `colima-setup`、`pnpm-setup`）

## front matter

qiita-cli でそのまま投稿できる形にします。

```yaml
---
title: Colimaのセットアップ&使い方(Docker)
tags:
  - Mac
  - Docker
  - colima
private: false
updated_at: ''
id: null
organization_url_name: null
slide: false
ignorePublish: false
---
```

- `title`: 記事タイトル。本文に `#` の見出しは書かない（タイトルがその役目）
- `tags`: 3〜5 個。記事の主題となる技術・ライブラリ・ツールのタグを先頭に必ず入れる（例: `Kysely`、`Temporal`）。残りは言語、プラットフォーム、関連技術の順に選ぶ
- Qiita に既存のタグ名を使う（`Swift`、`iOS`、`Docker`、`ClaudeCode` など）。主題のタグが存在するかわからない場合は、Qiita で検索して確認する。確認せずに主題のタグを省かない
- 主題に対応する既存タグがない場合のみ、そのタグを省く。造語のタグは付けない
- 他は上記のまま。`id` と `updated_at` は投稿時に qiita-cli が埋める

タイトルは記事の内容がそのままわかる短い名詞句にします。

- ⭕ `pnpmのセットアップ&使い方`
- ⭕ `onAppearとtaskの違いと使い分け(SwiftUI)`
- ❌ `【徹底解説】pnpmを使いこなすための完全ガイド`

## 本文の構造

この骨格で書きます。テンプレートは `assets/template.md` にあります。

```markdown
:::note info
本記事の執筆にはAIを使用しています。
:::

## はじめに

（記事の内容を一言で伝える）

## 「○○」とは？

（ライブラリや CLI ツールなどの紹介記事の場合のみ）

## 環境

（OS やライブラリなどのバージョンを箇条書きにする）

## （自由）

（記事の本質。テーマによって見出しの数などを柔軟に変える）

## おわりに

（記事の総括やまとめを一言で伝える）

## 参考リンク

（執筆にあたり参考にしたページの URL を箇条書きにする）
```

### 冒頭の note

一字一句この通りに書きます。読者への断りなので、省略も改変もしません。

### はじめに

記事の内容を 1〜3 文で伝えます。「〜を紹介します。」で終わる形が基本です。

> Colimaのセットアップ方法と使い方を、Dockerランタイムに絞って紹介します。

前置きは書きません。「近年〜が注目されています」のような枕は不要です。

解説記事など、前提の共有が必要なときはもう少し長くしてよいです。「本記事では〜します」で締め、読者が何を得られるかを示します。

### 「○○」とは？

ライブラリや CLI ツールなどの紹介記事のときだけ書きます。自作物の解説や、概念の解説記事では省きます。

1 行で「何であるか」を言い切り、空行を挟んで公式リポジトリか公式サイトの URL を単独行に置きます。Qiita では単独行の URL がリンクカードになります。

```markdown
## 「Colima」とは？

macOS用のコンテナランタイムです。

https://github.com/abiosoft/colima

OSSであり、Docker Desktopの代替としてよく使われています。
```

### 環境

記事を再現するのに必要なものだけを、`- 名前: バージョン` の箇条書きにします。

```markdown
## 環境

- macOS: Tahoe 26.3.1 (a)
- Colima: 0.10.1
```

バージョンは実際に動かしたものを書きます。わからないなら聞くか、コマンドで調べます。関係ないものまで並べると読みづらくなるので入れません。

### 自由セクション

記事の本質です。テーマに合わせて見出しを組みます。よくある型を挙げます。

| 記事の型 | 見出しの例 |
|:--|:--|
| セットアップ系 | `## セットアップ` → `### ○○のインストール` / `### 補完の設定`、`## 使い方` |
| 一覧・まとめ系 | `## ○○でよく使うコマンド一覧`（表で示す） |
| 解説・ハマりどころ系 | `## 悪い例を修正する` → `### {問題}`、`## まとめ` |

型に無理に当てはめる必要はありません。伝えたい順に見出しを立てます。

手順を追う記事では、読者が上から実行すればそのまま動く順番にします。エラーが出る箇所は、実際のエラーメッセージを貼ってから直し方を書くと、読者が検索でたどり着けます。

### おわりに

記事の総括を 1〜3 文で書きます。前向きに締め、読者へ柔らかく呼びかけます。

> Docker Desktopを使わなくても簡単にDockerコンテナを起動できました :relaxed:
>
> ColimaはDocker以外にContainerdやIncusのランタイムにも対応しているので、Dockerを使っていなくてもぜひ使ってみてください。

「いかがでしたでしょうか」は書きません。

### 参考リンク

執筆にあたり見たページの URL を、生の URL の箇条書きで並べます。

```markdown
## 参考リンク

- https://github.com/pnpm/pnpm
- https://pnpm.io/
```

**ここは手を抜かないでください。** 参考にしたのに書かないと、他人の記事を盗用したと疑われます。公式ドキュメント、GitHub の Issue や Discussion、他の人の記事、X のポストなど、内容の元になったものはすべて挙げます。本文中でリンクカードとして既に示した URL は、重複するので書かなくてよいです。

参考にしたページが 1 つもないということは、まずありません。何も見ずに書いたなら、その旨を確認してください。

## 記法

Qiita 独自の記法があります。よく使うものを挙げます。詳細は `references/qiita-markdown.md` を読んでください。

`references/qiita-markdown.md` はチートシート記事の写しです。Qiita 公式が随時更新するので、**使いたい記法がそこに載っていなければ、出典を取得して確認してください**。

https://qiita.com/Qiita/items/c686397e4a0f4f11683d

### 見出し

`##` から始めます。`#` は使いません。タイトルが `#` の役目を果たすためです。

### 段落と改行

Qiitaは改行がそのまま反映されます。**一文ごとに改行し、関連する文の間には空白行を入れません。**話題が変わるところだけ空白行を入れ、段落を分けます。

```markdown
私はmiseを使ってインストールします。
グローバルにインストールする場合は `--global` オプションを付けてください。

プロジェクト単位で使う場合は、ローカルへインストールします。
```

### インラインコード

コマンド名・型名・ファイル名・オプションはバッククォートで囲みます。日本語の文中では、**英単語の前後に半角スペースを入れません**。ただし、**バッククォートの前後には半角スペースを入れます**。

```markdown
⭕ 以下を参考に `docker compose` を実行できるようにします。
❌ 以下を参考に`docker compose`を実行できるようにします。
```

### コードブロック

言語を必ず指定します。ファイルパスがあれば `言語:パス` と書きます。

- シェルは `shell-session`。コマンド行に `$ ` を付け、出力もそのまま貼る
- 差分は `diff_{言語}`（例: `diff_bash:~/.bashrc`）。行頭に `+` `-` を付ける

````markdown
```shell-session
$ colima start
INFO[0000] starting colima
INFO[0000] runtime: docker
```
````

````markdown
```diff_bash:~/.bashrc
+ # pnpm
+ if type 'pnpm' > /dev/null 2>&1; then
+   eval "$(pnpm completion bash)"
+ fi
```
````

エラーの再現も、実際の出力をそのまま貼ります。整形したり省略したりすると、読者が検索で見つけられなくなります。

### リンク

- 記事の流れの中で参照するページ → 単独行に生 URL を置いてリンクカードにする（前後に空行が必要）
- 文中で軽く触れる → `[表示名](URL)` のインラインリンク
- 「参考リンク」セクション → `- URL` の箇条書き

### 引用

他のページの文章をそのまま載せるときは、引用ブロックを使い、**直後の行に `引用: {URL}` を書きます**。

```markdown
> 現在、Docker Desktop は大企業での利用が有償となっています。

引用: https://www.docker.com/pricing/
```

どこからの引用かが読者にわかり、盗用を疑われずに済みます。出典を書けない文章は載せません。

`引用: {URL}` で出典を示せているので、「参考リンク」に重ねて書く必要はありません。

### 表

左寄せで揃えます。

```markdown
|コマンド|説明|備考|
|:--|:--|:--|
|`/clear`|コンテキストをリセットする||
```

### 絵文字

Qiita 記法（`:relaxed:` など）を使います。「おわりに」で 1 つ添える程度にとどめます。

## 文体

`uhooi-writing` スキルを必ず使います。特に次を守ります。

- ですます調
- 一文一意で短く言い切る
- 平易な日常語を選ぶ。難しい単語は避ける
- 箇条書きの各項目に句点（。）を付けない
- 見出し代わりに太字を使わない
- 失敗やハマったことも率直に書く。背伸びしない

AI が書いた文章に見える表現は避けます。

| 避ける | 書き換える |
|:--|:--|
| 本記事では〜について解説していきます | 〜を紹介します |
| いかがでしたでしょうか | （書かない） |
| ぜひ活用してみてはいかがでしょうか | ぜひ使ってみてください |
| 〜することが可能です | 〜できます |
| 〜という点に注意が必要です | 〜に注意してください |
| 近年〜が注目されています | （書かない） |

## セルフチェック

書き終えたら確認します。

- [ ] 冒頭の note が一字一句そのままある
- [ ] `#` の見出しを使っていない
- [ ] 「はじめに」「環境」「おわりに」「参考リンク」がある
- [ ] 「参考リンク」に、執筆で見たページを漏れなく書いた
- [ ] 引用ブロックすべての直後に `引用: {URL}` がある
- [ ] 環境のバージョンが実際のものになっている
- [ ] コードブロックすべてに言語を指定した
- [ ] 一文ごとに改行している
- [ ] 関連する文の間に空白行を入れていない
- [ ] 話題が変わるところに空白行がある
- [ ] 日本語文中の英単語の前後に半角スペースがない
- [ ] 日本語文中のインラインコードの前後に半角スペースがある
- [ ] 箇条書きの末尾に句点がない
- [ ] front matter の `tags` が 3〜5 個で、Qiita の既存タグになっている
- [ ] 記事の主題となる技術・ライブラリ・ツールのタグが先頭にある

書き終えたら、保存先のパスと、付けたタグを伝えます。
プレビューしたいときは次のコマンドを案内します。

```bash
npx qiita preview
```
